# Algorithms that must stay constant-time clean under tests/ct/test_ct.
#
# CI (the "Constant-Time Verification (ctgrind)" job in ci.yml) runs these
# under Valgrind and fails if any of them reports a branch or memory index
# that depends on secret data, or fails to round-trip.
#
# An algorithm belongs here once it is (a) functionally correct and
# (b) clean. Everything else is still run weekly by security.yml and
# reported, but does not fail the build; see the "Known issues" section of
# CHANGELOG.md for what those runs find.
#
# Larger stateful parameter sets (LMS H15 and up, XMSS 16 and 20) are left
# out only for run time: their key generation builds 2^15 to 2^25 leaves,
# which takes too long under Valgrind for a per-commit job. They share the
# signing code with the sets listed.
